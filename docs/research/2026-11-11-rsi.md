# signoz-cli 的 RSI 实验

日期：2026-11-11。目标：让一次工具使用或代码检查发现的失败，变成下一轮
改进的可执行约束。本轮采用有边界的工程闭环，不宣称模型能力获得递归提升。

## 方法选择

[Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) 通过修改 Agent 代码、
实测候选版本、保留历史候选来探索自我改进。
[Anthropic 的 Agent 评测实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)
强调评测真实结果、保存执行轨迹，并区分任务、试验和评分器。

对这个 Rust CLI 的工程判断是：先让失败驱动工具和评测共同迭代，复用现有
Cargo 测试、mock server 和发布检查。暂不引入候选分支搜索、LLM 评分器、
后台循环或新的依赖；当前没有足够的任务数据证明这些设施值得维护。

| 路径 | 当前依据 | 本轮选择 |
| --- | --- | --- |
| 修改 CLI 实现并运行确定性测试 | 已有请求、输出、错误码测试 | 执行 |
| 修改 Skill 并评测 Agent 完成任务的结果 | 已有场景和历史记录，但自动检查只匹配文本 | 留待有真实执行轨迹时进行 |
| 自动生成多个候选并持续搜索 | 尚无固定任务集、成本预算和停止策略 | 暂不实现 |

## 可重复的改进循环

1. 记录失败输入、预期结果、实际结果和影响；只保存脱敏样本。
2. 在修改实现前添加回归测试并确认失败。区分代码失败与环境限制。
3. 检索调用方，在共享实现修复根因；保持公共接口和合法输入行为。
4. 除原始反例外，检查相邻合法输入以及不同输入路径，防止只修好一个样本。
5. 运行 CONTRIBUTING 中现有检查。不得通过删掉失败用例、放宽断言或修改
   预期来证明候选更好；若预期确实错误，先独立记录契约依据。
6. 保留能通过回归及邻近场景的最小改动，记录证据和未验证项；可见行为变更
   按现有版本规则准备一次版本。提交、推送和发布仍遵守用户授权范围。
7. 下一轮使用累积的回归集作为基线。没有新的可复现失败时停止，不为循环
   本身持续生成改动。失败候选不进入发布；保留失败输入供后续调查。

不要把静态检查的通过率称为 Agent 任务成功率。现有
`scripts/validate-agent-integration.py` 验证 Skill 文本和包结构，
`tests/skill/scenarios.json` 的关键词并不能证明 Agent 实际执行了正确命令。
将来评测 Skill 时，应固定工具版本、环境和任务，保存脱敏命令轨迹，检查
最终输出、环境选择及分页完整性，并记录多次试验的结果和成本。

## 首轮：时间计算的边界反例

基线提交：`9c8be40`，产品版本：`0.6.1`。已有 Rust 测试 139 项通过。
第一次运行被沙箱禁止绑定 mock server 端口；允许本机端口后基线全绿，
因此不把该环境失败计作产品缺陷。

| 反例 | 修复前观察 | 接受标准 |
| --- | --- | --- |
| 客户端 `now = -2ms`，`since = i64::MAX ms` | debug 下减法下溢 panic | 返回错误；`now = -1ms` 时仍允许合法的 `i64::MIN` 起点 |
| Meter 绝对范围 `@i64::MIN` 到 `@i64::MAX` | 起点整点对齐的中间乘法溢出 panic | 得到区间内部可表示的完整小时边界 |
| Meter 端点靠近整数极限；或相对范围对齐后越界 | 极端绝对范围 panic；相对路径存在饱和截断 | 返回 validation，不能静默缩短范围 |

先新增的三个回归测试均在原实现失败。修复使用 checked arithmetic，以及
余数求整点，避免先生成越界的中间值；没有新增公共 API 或收窄一般时间戳范围。
补充 Unix epoch 两侧和已对齐小时的合法输入，以及 CLI 无连接配置时的
结构化错误测试。极端时间主要用于暴露算术缺陷，不代表常规查询会触发它。

复现相关检查：

```sh
cargo test -p signoz-client --lib --locked relative_windows_
cargo test -p signoz-cli --locked meter_
cargo test --workspace --locked
```

新增用例随现有 Cargo 测试自动进入 CI。它们衡量时间计算与错误契约，
不衡量 Agent 智能、真实 SigNoz 兼容性或线上查询性能。未连接真实实例，
未运行新的模型级 Skill 评测，未建立常驻自修改服务。

本轮验收：144 项 Rust 测试（比基线新增 5 项）、9 项 Node 安装器测试、
12 项 Python 测试通过；fmt、clippy、Agent 集成、release metadata 和 diff
检查通过。按兼容修复准备 `0.6.2`，不改变 JSON schema version。

本机 CLI 和 Codex 插件已刷新为 `0.6.2`；两个 Agent 的独立 Skill 与插件缓存
内容均核对一致。npm tarball 冒烟检查首次选中了遗留 `0.4.0` 产物，显式设置
`SIGNOZ_TEST_BINARY` 为本次安装的二进制后通过。这是测试输入版本不一致，
不计作本轮产品缺陷。构建还提示锁定依赖 `chacha20 0.10.1` 已被 registry
撤回；安装成功，本轮未更新依赖。没有提交、打 tag、推送或发布。

## 第二轮：响应体中断后的恢复

基线为首轮完成后的 `0.6.2` 工作区（144 项 Rust 测试通过），未提交到 Git。
检查共享 `HttpTransport` 及所有调用方后发现：发送请求失败会进入重试，
但收到响应头后的 `read_bounded` 错误直接通过 `?` 返回，绕过重试。
这不符合 README 对 transport failures 的三次尝试约定。

新增 TCP 夹具发送 HTTP 200 和较大的 Content-Length，只发送部分正文后断开。
wiremock 正常完成正文，不能替代这个断流场景。两个新增反例在修复前失败：
原本可在第三次恢复的 GET 直接返回 Network；持续断流只收到一次请求。

修复在现有循环中重试响应读取的 Network 错误，沿用 replay_safe、退避和
包住整个循环的 timeout。没有增加依赖、修改公共接口或扩大重试次数。
评测同时检查：

- GET 连续两次断流后第三次成功；重试成功前不解析不完整 JSON。
- POST 持续断流在可重放时最多三次，在不可重放时只有一次。
- 250ms 总预算会在重试期间返回 Timeout，不能为每次尝试重置预算。
- 完整传输但内容不是合法 JSON、超过大小上限的响应各只请求一次。
- 既有认证、API key 脱敏、禁止重定向和代理路径测试继续通过。

测试夹具最初在 macOS 上继承了非阻塞 socket 模式，读取时报 WouldBlock；
显式切回阻塞读取后消除该夹具问题。没有放宽产品断言来掩盖失败。
本轮把正文中断与发送失败分开覆盖，后续重试改动必须保留这两条路径。

```sh
cargo test -p signoz-client --test http --locked
```

这些测试使用本机 HTTP/TCP，不代表已验证公网代理、TLS 断流或真实 SigNoz。

验收：新增 4 项测试，共 148 项 Rust 测试通过；9 项 Node 安装器测试、
12 项 Python 测试、fmt、clippy、Agent 集成、release metadata 和 diff
检查通过。按兼容修复准备 `0.6.3`，保留首轮 `0.6.2` 的实验和变更记录。
本机 CLI、Codex 插件已更新为 `0.6.3`，独立 Skill 和插件缓存内容核对一致；
显式指定新安装二进制的 npm tarball 冒烟检查通过。没有提交或发布。

## 第三轮：路径参数与跨 CLI 回归

接续已完成的 0.6.3 工作区，与 langfuse-cli、mongodb-cli 同轮检查。
共用 `segment` 使用表单编码，导致资源 ID 的空格变成路径中的字面 `+`。
先扩展已有回归用例，确认规则、仪表盘、视图、通道的空格、加号、斜线、
查询/片段分隔符和中文组合输入失败；再只将表单编码产生的 `+` 转成 `%20`，
保留原有字面加号的 `%2B` 及其他百分号编码。

同步采用上一轮 mongodb-cli 验证过的 chacha20 0.10.2 补丁，替换已撤回版本；
补充系统元数据的 gitignore 规则。本轮结束后按用户要求提交累计 RSI 改动，
后续每轮也在验证完成后提交；推送和发布仍需单独授权。

0.6.4 验收：148 项 Rust 测试、9 项 Node 测试、12 项 Python 测试通过；
fmt、clippy、Agent 集成、发布一致性检查通过。未验证真实 SigNoz 或其他操作系统。
本机 CLI、独立 Skills 与既有 Codex 插件缓存已更新并核验；指定本轮二进制的 npm tarball 冒烟检查通过。

## 第四轮：时间单位转换不能静默截断

0.6.4 的共用 nanos 使用 i64 饱和乘法，极端合法毫秒输入被静默换成另一时间点。
新增一个回归用例覆盖 services、operations、dependencies、exceptions list/count 五条路径，
在原实现失败。改用 i128 中间值后输出精确的十进制纳秒字符串，不改变公共接口和正常日期行为。
服务端仍可拒绝不支持的时间范围；本轮只验证转换正确，不宣称真实服务支持极端时间戳。
0.6.5 验收：149 项 Rust 测试、9 项 Node 测试、12 项 Python 测试及 fmt、clippy、
Agent 集成和版本检查全部通过。未验证真实 SigNoz 或其他操作系统。
本机 CLI、Skills 和 Codex 插件更新至 0.6.5 并核验内容，npm tarball 冒烟检查通过。

## 第六轮 RSI：请求与结果的相邻边界

上游报告 hasMore=true 但返回空页时，原实现的 nextOffset 等于当前 offset；u32 上界相加也会饱和到同一值。先添加失败反例，再使用 checked_add 和严格前进条件；仍保留 hasMore 与返回数据，并说明应收窄查询。邻近合法上界仍可分页。

## 第七轮 RSI：异常结果与诊断恢复

旧 tolerant_data_array 将任意非数组 data 替换为空数组，导致 views/channels 响应异常仍报告零条。失败反例覆盖对象、字符串、数字和布尔值；修复复用 array_or_null，仅保留缺失/null 的兼容性。CLI 测试确认异常返回 exit 7、不输出数据或泄露载荷；原正常空列表测试继续通过。
